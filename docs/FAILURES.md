## Requested 9:16 returned 3:4 with HTTP 200

- **Mode:** image-to-video
- **Severity:** high
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Minimax H3 Max (image-to-video)
- **Evidence recipes:** [Fictional adult character idle loop](../examples/guoguo-idle-loop.json), [Fictional adult character hair-touch reaction](../examples/guoguo-hair-reaction.json)

**Symptom.** Both requests set ratio to 9:16 and both returned a 200 response with a playable MP4. The measured output was 480x640, which is 3:4, not 9:16. Nothing in the HTTP response indicated the request had not been honored.

**Reproduction.** Submit an image-to-video request with ratio 9:16, resolution 480P, durationSeconds 5, promptExpansion false. Download the completed file and run ffprobe instead of trusting the request echo.

**Detection.** Parse width and height from the downloaded file with ffprobe. Do not read dimensions from any API response field, and do not infer the ratio from the request you sent.

**Mitigation.** Probe the output, then crop or pad to the delivery ratio in post. Do not re-submit hoping for a different result; both runs behaved identically.

**Why it matters.** A vertical-first pipeline that trusts the request parameter will ship a 3:4 video into a 9:16 slot. Every downstream crop, thumbnail, and player layout then breaks.

**Notes.**
- Reproduced twice on the same model with the same parameters, so this is not a transient failure.
- The Wan 3.0 run in this same database DID honor its requested duration and resolution, so this cannot be generalized to all providers.

## Reference-to-video does not lock the reference as frame one

- **Mode:** reference-to-video
- **Severity:** high
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Grok Imagine Video 1.5
- **Evidence recipes:** [Fictional adult character reference-to-video test](../examples/guoguo-reference-grok.json)

**Symptom.** The reference image was supplied as the sole identity reference. The returned clip's opening frame differs from that reference in pose, framing, and room. The gold dress, bow, and hairstyle remain recognizable, but facial proportions visibly change across the clip.

**Reproduction.** Submit a reference-to-video request with one reference image and a prompt that asks to preserve face, hairstyle, clothing, and proportions. Compare the output's first frame against the reference image.

**Detection.** Extract the output's first frame and compare it to the reference side by side. A prompt that says 'preserve' is not a guarantee and is not a test.

**Mitigation.** If you need a locked first frame, use a true image-to-video or first-frame mode instead of reference-to-video. Treat reference-to-video as a soft identity hint.

**Why it matters.** Reference-to-video is routinely marketed as consistent-character generation. It is not identity verification. Workflows that cut between shots generated this way will show visible face changes.

**Notes.**
- This is a mode-selection error, not a model defect. The same model's image-to-video path was not tested here.
- The limitation is recorded in the recipe itself, not just here, so the claim and the counter-evidence stay together.

## A hand crossing the face is a worst case for anatomy artifacts

- **Mode:** image-to-video
- **Severity:** medium
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Minimax H3 Max (image-to-video)
- **Evidence recipes:** [Fictional adult character hair-touch reaction](../examples/guoguo-hair-reaction.json)

**Symptom.** A prompt asking the character to push a strand of hair behind the ear, with fingertips grazing the jaw, produced the intended gesture but this remains the highest-risk configuration in the set for finger, hair, jawline, and identity artifacts.

**Reproduction.** Submit an image-to-video request where a hand travels across the face or jaw, then step through every frame.

**Detection.** Step through the clip frame by frame at the point of contact. Aggregate quality metrics will not surface this.

**Mitigation.** Prefer gestures that do not occlude the face. When occlusion is required, budget for per-frame review and reshoots.

**Why it matters.** Hand-to-face is one of the most requested motions in character work and one of the least reliable. Recording it as a stress test keeps the expectation honest.

**Notes.**
- Recorded as a known-limitation stress test rather than a failure of the specific run, because the run did complete the requested gesture.

## Two independently generated shots of the same character do not verify as one face

- **Mode:** text-to-video
- **Severity:** medium
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Grok Imagine Video 1.5

**Symptom.** Two separate 4.04 s clips generated from text prompts describing the same character both produced a black-haired figure in a black dress inside a hotel environment, but shot one is a rear view in a corridor and shot two is a front/side view at a rain window. The face is not visible in both, so the two shots cannot be verified as the same person.

**Reproduction.** Generate two shots from separate text-to-video requests describing one character, concatenate them, then try to verify identity across the cut.

**Detection.** Watch the cut. If the face is not on screen in both adjacent shots, no continuity claim is supportable regardless of how consistent the prompt was.

**Mitigation.** Either keep the face on screen in every shot you intend to splice, or use a locked identity mechanism. Do not describe the same character and assume the model resolves identity.

**Why it matters.** Multi-shot scenes are the main reason people stitch AI clips. Prompt reuse across shots does not produce a continuous character.

**Notes.**
- Evidence lives in huangguo.design's public evidence directory: grok-storyboard-shot-1.mp4, grok-storyboard-shot-2.mp4, and the concatenated grok-storyboard-two-shot.mp4 (SHA-256 4a3171e70204983e72388133a74e9e9e55c59367f965fdead786da502ae77f58).
- Not yet formatted as standalone recipes in this repository; tracked as a gap.

## Public artifact is a lossy web derivative, not the provider response

- **Mode:** image-to-video
- **Severity:** medium
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Wan 3.0 (image-to-video)
- **Evidence recipes:** [Neon-city two-character motion test](../examples/dushi-neon-couple.json)

**Symptom.** The provider response was transcoded to a 1920x1080 site master and then deleted. The only publicly available file is a 720x406, 15 fps, CRF 31 derivative without audio. Anyone measuring the public MP4 is measuring the derivative, not the model output.

**Reproduction.** Compare the recorded transcoded master SHA-256 against the public file's SHA-256. They differ by design.

**Detection.** Check whether the URL you are about to cite is the provider's own response URL. If it points at your own CDN, you are citing a re-encode.

**Mitigation.** Either keep the provider response byte-for-byte, or label the derivative explicitly and publish the master's hash so the gap is auditable.

**Why it matters.** Quality claims built on re-encoded derivatives are not reproducible. This is why the recipe records the master hash instead of quietly substituting the derivative.

**Notes.**
- Transcoded master SHA-256: 467a23963d980057622304a28368ad7a3fe5859c10c4954f671e061d4612fd90.
- This entry is a documentation hazard rather than a model bug, but it silently invalidates any benchmark that scrapes public URLs.

## Reverse-concat loop doubles duration and breaks asymmetric gestures

- **Mode:** post-processing
- **Severity:** low
- **Status:** confirmed
- **First observed:** 2026-09-04
- **Models:** Minimax H3 Max (image-to-video)
- **Evidence recipes:** [Fictional adult character idle loop](../examples/guoguo-idle-loop.json)

**Symptom.** A 5-second model output was concatenated with a reversed copy to create a palindrome loop, producing 10.33 s. The loop works for symmetric idle motion but makes any asymmetric gesture read as an unnatural rewind.

**Reproduction.** Take a clip whose opening and closing poses differ, concatenate it with its reverse, and watch the join.

**Detection.** Compare the last frame of the forward clip against the first frame. If they differ meaningfully, do not palindrome it.

**Mitigation.** Use palindrome looping only for genuinely symmetric motion like breathing or idle sway. For directional gestures, generate a longer single take or trim to a shorter loop.

**Why it matters.** It is the cheapest way to lengthen a short clip and therefore the most commonly overused. It fails exactly where people most want it to work, on gestures.

**Notes.**
- The recipe explicitly notes the final frame is close to but not guaranteed to equal the opening pose.
